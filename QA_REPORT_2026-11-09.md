# URI QA Audit — 9 November 2026

**Scope:** Wedding creation, both templates, invitation editor, Photo Manager, venue/timeline editor, readiness, Dashboard 2.0, local guest management and RSVP, and the existing publication integration.

**Assessment:** The browser-local wedding MVP passes the automated regression journey. The app is not yet ready for production guest use.

## Verified testing

- GitHub Actions: full Node smoke-test job and headless Chromium browser-qa job completed successfully on recent commits. See [URI Actions](https://github.com/mawruemdota/URI/actions).
- Chromium journey at 1440×900 and 390×844: wizard, cover/gallery uploads, crop and zoom, drag reorder, both designs, reload persistence, venue and timeline editing, duplication and deletion, local RSVP and analytics. Screenshots are in the Actions artifact named uri-wedding-browser-screenshots.
- Node tests include all 42 feature/template combinations, data privacy, malformed drafts/URLs, failed storage writes, image isolation across events, and RSVP capacity checks.
- Supabase URI project was ACTIVE_HEALTHY. Its security and performance advisor results were empty; its publications table contained zero records at inspection. This is not an end-to-end cloud publishing test.

## Remaining production blockers

1. **Online RSVP is not implemented.** Local test URLs and responses work only in the same browser and are not secure or cross-device.
2. **Live cloud publishing is not end-to-end verified.** Configure permitted Supabase authentication redirect URLs; test real email sign-in, publish, separate-browser view, update and unpublish.
3. **Unpublishing does not delete public media objects.** Establish an image deletion/retention policy before use with real wedding photographs.
4. **Drafts are device-local** and subject to browser storage quotas and clearing. Account-backed drafts and media are needed for production.
5. **iOS Safari and Android Chrome still require real-device QA**, especially file inputs, touch panning, keyboard focus, and accessibility. Chromium success is not a WCAG accessibility audit.
6. **Dashboard published status is local metadata**, not a live database read.

## Release gate

Do not launch to real invitees until secure guest RSVP, cloud ownership/publishing tests, media retention behavior, cross-device testing and real-device QA are complete. Keep local-demo warnings visible until then.

Review [URI Builder Checks](https://github.com/mawruemdota/URI/actions/workflows/builder-tests.yml) and the screenshot artifacts after each release candidate. A failing run should block release.
